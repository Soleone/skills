# Routing acceptance scenarios

Use these to review changes to the skill. They are specification cases, not executable LLM evaluations. Do not load this file during ordinary prototype work.

| Request/context | Required behavior | Failure to catch |
| --- | --- | --- |
| New form; no preset or approved reference | Brief; propose one preset/base; label the first composition provisional; confirm blocking choices before setup | Inventing a vetted template or a custom visual system |
| Fully specified form in existing app | Read incumbent design and components; state interpretation and proceed without repeated discovery | Replacing theme or forcing a new Vite app |
| Impeccable absent | Complete the normal workflow with shadcn and available browser tooling | Requiring installation of Impeccable |
| Impeccable present or required by host | Keep Operate/product constraints; follow its setup if used; retain approved visual authority | Treating expressive guidance as permission to redesign |
| shadcn companion absent | Finish brief, report component-work prerequisite | Guessing API examples or inventing controls |
| “Move Save below these fields” annotation | Inspect current source/DOM; move the action; check affected layout/keyboard behavior | Reopening theme or adding panels |
| Etch captures arbitrary button radius/color | Translate intent to allowed variants/tokens; ask if an exception is necessary | Pasting browser CSS directly into source |
| Theme-only change | Conditional theming workflow, preserve UI source/interaction and unrelated work | Reinstalling components or migrating primitive base |
| Critique this prototype, no changes | Findings against the contract; optional requested specialist; no edits | Silently implementing recommendations |
| Make a bold campaign landing page | Route outside this skill's task-oriented app workflow | Applying stock-form restrictions to marketing |
| Browser cannot connect | Report unverified preview and blocker | Claiming screenshots, accessibility checks, or a visual pass |
| pi-annotate unavailable | Disclose limitation, accept screenshot/text feedback | Installing a second annotation library without permission |
| Validation still fails after confirmation | Report failures and stop expanding scope | Calling the prototype finished or polishing indefinitely |
| Approved UI now needs real persistence | Retain UI and identify mock boundaries; agree separate integration scope | Claiming visual approval means production-ready |

For a live pilot, record observed behavior against the relevant rows. Static inspection of these cases is not a behavioral test result.
